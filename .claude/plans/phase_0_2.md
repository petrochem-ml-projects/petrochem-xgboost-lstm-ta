## 1. Objective

**Purpose.** Give all three machines (macOS / Windows / Ubuntu) the
*identical* Python toolchain from committed files alone: `uv` manages the
interpreter, the venv, and a cross-platform lockfile; pre-commit enforces
lint/format/type gates automatically. After this item, "works on my
machine" stops being a possible sentence for tooling reasons (§12.1).

**Business objective.** Three developers must be able to onboard with the
literal §12.9 command sequence and get byte-identical dependency
resolutions. Every later phase's code lands on top of this configuration —
getting Ruff/mypy/pytest settings right *now* means no mass-reformatting
PRs later.

**Deliverables.**
- `pyproject.toml` — project metadata, core deps, all 10 optional-
  dependency extras, plus `[tool.ruff]`, `[tool.mypy]`,
  `[tool.pytest.ini_options]` configuration.
- `.python-version` containing `3.11`.
- `uv.lock` — committed, generated by `uv sync --all-extras`.
- `.pre-commit-config.yaml` per §12.1, hooks installed for both
  `pre-commit` and `pre-push` stages.
- One minimal sanity test (`tests/test_sanity.py`, marker `unit`) so the
  pre-push hook and the Phase-0 gate command (`uv run pytest -m unit`)
  have a green, non-empty suite to run (see §6-D3).

**Scope.** Only the above.

**Out of scope (deferred to their own items).** Package directory tree +
`__init__.py` files, `config.py`, `.env.example` (0.3); CODEOWNERS, PR
template, labels/Milestones (0.4); CI workflow, `interrogate` docstring
threshold enforcement, coverage `fail_under` gating (0.5 — see §6-D6);
`docker-compose.yml` / Dockerfiles (Phase 1, §4.17); any application code.

## 4. Detailed Implementation Plan

Four tasks, strictly ordered.

### T1 — `pyproject.toml`
- **Creates:** `pyproject.toml` at repo root. Modifies nothing.
- **`[project]`:** name, version `0.0.1` (pre-first-release; §12.12 tags
  start at Phase-1 completion), `requires-python`, core dependencies —
  all verbatim per Q1. Add `description` and `readme` omitted (no README
  yet — 0.4/later; leaving `readme` out avoids a build error on a missing
  file).
- **`[project.optional-dependencies]`:** the ten extras verbatim from
  §12.1. Unversioned entries stay unversioned (the lockfile pins them).
- **Build system:** none — this repo is an application, not a distributable
  package; uv treats it as a virtual project without `[build-system]`,
  which also spares `uv sync` from needing package discovery across
  not-yet-existing directories. Revisit only if a phase ever needs
  `pip install .` (see §6-D2).
- **`[tool.ruff]`:** `line-length = 100`; `[tool.ruff.lint]` `select =
  ["E","F","I","UP","B","C4","SIM","D","ARG","RUF"]`;
  `[tool.ruff.lint.pydocstyle]` `convention = "google"`;
  `[tool.ruff.lint.per-file-ignores]` — `tests/**: ["D"]` (docstring
  rules on test functions add noise, §12.13's docstring mandate targets
  *public modules*; see §6-D4).
- **`[tool.mypy]`:** `python_version = "3.11"`, `disallow_untyped_defs =
  true`, `warn_return_any = true`. Nothing stricter (Q7).
- **`[tool.pytest.ini_options]`:** `markers` list with one-line
  descriptions for the four tiers (Q8); `addopts = "-m unit"` is **not**
  set (each caller states its tier explicitly; CI runs tiers separately
  per §12.11); `testpaths = ["tests"]`.
- **Validation:** `uv sync --all-extras` resolves and installs; `uv run
  ruff check .` and `uv run mypy .` exit 0 on the (near-empty) tree.

### T2 — `.python-version` + `uv.lock`
- **Creates:** `.python-version` (single line `3.11`); `uv.lock`
  (generated, then committed).
- **Algorithm/order:** write `.python-version` → run `uv sync
  --all-extras` (uv fetches CPython 3.11 if needed, creates `.venv/` —
  already gitignored — resolves every extra including torch/tensorflow/
  airflow, writes `uv.lock`) → commit the lockfile.
- **Known heavy step:** `--all-extras` pulls PyTorch + TensorFlow +
  Airflow (multi-GB, minutes). Expected and per §12.1 for dev machines;
  Docker images later install per-service extras only.
- **Risk to watch:** Airflow is famously constraint-sensitive and
  TensorFlow's Windows support is CPU-only via its intel wheel. If
  resolution fails or conflicts, pin the offending package to a known-good
  version in the extra (a `docs/*`-typed follow-up updates CLAUDE.md §12.1
  if a pin becomes permanent). Do not silently drop an extra.
- **Validation:** `uv.lock` exists and `git status` shows it staged (not
  ignored); a second `uv sync --all-extras` is a no-op ("Resolved … no
  changes").

### T3 — `.pre-commit-config.yaml` + hook installation
- **Creates:** `.pre-commit-config.yaml` verbatim from §12.1's YAML block
  (repos: ruff-pre-commit `v0.6.0` with `ruff` + `ruff-format`;
  mirrors-mypy `v1.11.0`; pre-commit-hooks `v4.6.0` with the five hooks
  incl. `mixed-line-ending --fix=lf`; local `pytest-unit` at
  `stages: [pre-push]`). Rev choice: §6-D5.
- **Per machine (×3):** `pre-commit install --hook-type pre-commit
  --hook-type pre-push` (documented in the PR description; the command is
  already the §12.9 onboarding step).
- **Validation:** `pre-commit run --all-files` green; a scratch commit
  triggers ruff/mypy/pre-commit-hooks only; a push to a scratch branch
  additionally triggers the pytest hook.

### T4 — Sanity unit test
- **Creates:** `tests/test_sanity.py` — one `@pytest.mark.unit` test
  asserting a triviality (e.g. the four markers are importable/registered,
  or `sys.version_info[:2] == (3, 11)` — the latter doubles as an
  interpreter-pin check).
- **Why it exists:** with zero collected tests, `pytest -m unit` exits 5
  ("no tests ran"), which would fail the pre-push hook and the Phase-0
  gate command. One real test makes the gate honest (§6-D3).
- **Interacts with:** 0.3 later adds `tests/__init__.py`; no conflict.
- **Validation:** `uv run pytest -m unit` → `1 passed`; `uv run pytest -m
  e2e` → `1 deselected` (markers filter correctly, no unknown-marker
  warning).

## 5. Detailed Step-by-Step Execution

1. **Branch:** `feature/0-2-tooling-skeleton` off up-to-date `main`
   (§12.4 prefix rules; include the issue number if 0.2 has a GitHub
   issue, e.g. `feature/3-tooling-skeleton`).
2. **Write `pyproject.toml`** per §4-T1. Responsibility: single source of
   truth for deps + tool config. Interacts with: every later Dockerfile
   (`--extra` installs), CI (0.5 reads nothing else), all future code
   (lint/type rules). Check: file parses — `uv lock --check` after T2, and
   `uv run python -c "import tomllib,pathlib;
   tomllib.loads(pathlib.Path('pyproject.toml').read_text())"` style
   sanity is implicit in `uv sync` succeeding.
3. **Write `.python-version`** (`3.11`, one line, LF). Check: `uv python
   find` resolves a 3.11 interpreter after sync.
4. **Run `uv sync --all-extras`.** Expected: 3.11 fetched if absent,
   `.venv/` created (ignored), `uv.lock` written. On failure, resolve per
   §4-T2's risk note — never proceed with an uncommitted-lockfile state.
5. **Write `.pre-commit-config.yaml`** per §4-T3. Check: `uv run
   pre-commit validate-config`.
6. **Write `tests/test_sanity.py`** per §4-T4 (with a module docstring —
   the `D` per-file-ignore covers test *functions*, keep the module
   docstring anyway as good practice).
7. **Install hooks:** `pre-commit install --hook-type pre-commit
   --hook-type pre-push`. Check: `.git/hooks/pre-commit` and
   `.git/hooks/pre-push` exist.
8. **Full local gate:** `uv run ruff check .`, `uv run ruff format
   --check .`, `uv run mypy .`, `uv run pytest -m unit`, `pre-commit run
   --all-files` — all green. Fix anything before pushing (mypy on the
   sanity test is the first real exercise of `disallow_untyped_defs` —
   the test function needs `-> None`).
9. **Commit + push** the five files (`pyproject.toml`, `.python-version`,
   `uv.lock`, `.pre-commit-config.yaml`, `tests/test_sanity.py`);
   observe the pre-push hook run the unit suite.
10. **Open the PR** titled per §9, description noting: lockfile size,
    resolution time, any pins added under §4-T2's risk clause, and the
    per-machine `pre-commit install` instruction.
11. **After merge:** on the other two machines, `git pull && uv sync
    --all-extras && pre-commit install --hook-type pre-commit --hook-type
    pre-push && uv run pytest -m unit` — record success per machine
    (this is most of the Phase-0 gate; §8-5).

## 6. Design Decisions

- **D1 — No `[build-system]` / virtual project.** Options: (a) declare
  hatchling/setuptools and package discovery; (b) uv virtual project, no
  build backend. **Chosen: (b).** Nothing imports this repo as an
  installed package — services run modules (`python -m data_generator.cli`).
  (a) would force package-discovery config for directories that don't
  exist until 0.3 and adds zero value now. Trade-off: if something later
  needs `pip install .`, add the backend then (one small PR).
- **D2 — Version `0.0.1`.** §12.12 ties minor bumps to completed phases
  (`v0.1.0` = Phase 1). Pre-Phase-1 work sits below that floor; `0.0.1`
  says "exists, nothing released".
- **D3 — Sanity test instead of tolerating pytest exit code 5.** Options:
  (a) wrap the hook in `|| [ $? = 5 ]`; (b) a plugin
  (pytest-custom-exit-code); (c) one real sanity test. **Chosen: (c).**
  (a) hides genuine collection errors (exit 5 also fires when a typo'd
  marker deselects everything); (b) adds a dependency for a non-problem.
  The sanity test also pins the interpreter version as a bonus assertion.
  Trade-off: `tests/` appears one item "early" (0.3 owns the tree) —
  accepted, the Phase-0 gate command literally requires a green suite.
- **D4 — Per-file-ignore `D` rules in `tests/**`.** §12.13's docstring
  mandate targets public modules; requiring Google-style docstrings on
  every test function generates noise that trains people to write
  boilerplate. Module-level docstrings in tests stay encouraged. This is
  config-level interpretation, not a CLAUDE.md conflict.
- **D5 — Use §12.1's pinned hook revs verbatim (`ruff-pre-commit v0.6.0`,
  `mirrors-mypy v1.11.0`, `pre-commit-hooks v4.6.0`).** Options: (a)
  verbatim; (b) `pre-commit autoupdate` to current. **Chosen: (a)** —
  "this document wins" (§ preamble); newer revs may flag different rules
  than CI's ruff (locked separately via `pyproject`). Trade-off: revs age.
  If drift between hook-ruff and venv-ruff ever produces conflicting
  verdicts, raise a `docs/*` PR updating §12.1's revs and this config
  together.
- **D6 — No coverage `fail_under` yet.** §12.8's ≥80% threshold is a gate
  on *real* code; enforcing it against one sanity test is meaningless
  (100%) and against 0.3's empty `__init__.py` tree, brittle. CI coverage
  reporting + threshold lands with 0.5, where §12.11 places it. Same
  deferral for `interrogate` (§12.11 step 7).
- **D7 — mirrors-mypy runs mypy in an isolated env without project deps.**
  Known limitation: once Pydantic models exist (Phase 1), the hook may
  need `additional_dependencies: [pydantic, …]` to type-check fully.
  Accepted now (there's no code); noted so Phase 1's first PR doesn't
  rediscover it. Keeping the mirror (vs a local `uv run mypy` hook)
  follows §12.1 verbatim — same escape hatch as D5 if it bites.

## 7. Testing Strategy

Tiers begin existing with this item. There is deliberately only one test:

| Tier | Content in this item |
|---|---|
| `unit` | `tests/test_sanity.py::test_environment_sane` — asserts interpreter is 3.11 (and, optionally, that pytest sees the four registered markers). Failure mode covered: wrong/system Python being picked up instead of uv's. |
| `integration` / `pipeline` / `e2e` | markers registered, zero tests — correct until Phases 1/5/6 respectively. |

Behavioral checks (the real verification for a tooling item), all part of
§5 steps 8–11:

| Check | Action | Expected |
|---|---|---|
| Reproducible resolve | `uv sync --all-extras` twice | second run no-ops |
| Lockfile honesty | `uv lock --check` | exit 0 (lock matches pyproject) |
| Commit gate fires | commit a file with trailing whitespace | hook fixes/blocks it |
| Format gate fires | commit an unformatted `.py` | `ruff-format` reformats, commit blocked until re-staged |
| Type gate fires | commit a def without annotations | mypy `disallow_untyped_defs` blocks |
| Push gate fires | `git push` with a deliberately failing unit test | push blocked; remove test, push passes |
| Marker filtering | `uv run pytest -m e2e` | `1 deselected`, exit 0? — **no**: exit 5 with everything deselected is acceptable *outside* the hook; the hook only ever runs `-m unit`, which has ≥1 test. Record actual behavior in the PR. |
| Cross-platform | §5 step 11 sequence on Windows + Ubuntu machines | all green; TF/torch import-sanity optional but recommended (`uv run python -c "import torch, tensorflow"`) |

Failure handling: any red check is fixed on the branch before merge — the
gates *are* the deliverable, an ignored red gate here normalizes ignoring
them forever.

## 8. Acceptance Criteria

1. `pyproject.toml`, `.python-version`, `uv.lock`,
   `.pre-commit-config.yaml`, `tests/test_sanity.py` exist on `main` via
   a squash-merged PR.
2. Fresh clone on any machine: `uv sync --all-extras` succeeds and a
   second invocation is a no-op; `uv lock --check` passes.
3. `uv run ruff check .`, `uv run ruff format --check .`, `uv run mypy .`
   all exit 0.
4. `uv run pytest -m unit` reports **1 passed** (not "no tests ran");
   `pytest` emits no unknown-marker warnings for any of the four tiers.
5. With hooks installed: a commit runs ruff/ruff-format/mypy/file-hygiene
   hooks; a push runs the unit suite; both demonstrably block on a
   planted failure (behavioral checks in §7 executed and recorded in the
   PR).
6. The §5-step-11 sequence has been run on all three machines and
   recorded in the PR (or, if a machine is unavailable, that's stated
   explicitly — not silently skipped). This, plus 0.3's skeleton, is what
   lets the Phase-0 gate be claimed later.
